# Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Named profiles under `~/.jas/profiles/<name>/` (skills, `AGENTS.md`, a settings layer), one active per session, chosen by flag/env/config and switchable in chat with `/profile`.

**Architecture:** `profile` becomes an ordinary setting resolved in two phases: first the name (flags, env, local, project, global), then that profile's `config.json` is slotted into `settings.Layers` between global and project. User skills come only from the active profile's `skills/` plus the built-in manual, read through a narrow, read-only deny-floor exception in `core.ExecPolicy`. The chat switches profile by rebuilding the env's profile state and reusing the `/reload` path.

**Tech Stack:** Go (CGO_ENABLED=0), Bubble Tea v2 inline TUI, existing `settings`, `skills`, `core`, `tui`, `cmd/jas` packages.

**Spec:** `docs/superpowers/specs/2026-11-11-profiles-design.md`

## Global Constraints

- Profile names match `^[a-z0-9]+(-[a-z0-9]+)*$`, at most 64 characters (same as skill names: `skills.validName`, `maxNameLen`).
- Settings order: flags > env > local > project > profile > global > defaults, for plain keys and for the `models.*` / `providers.*` maps.
- A profile layer may not set `provider`, `base_url`, `search_base_url`, `providers.*` or `profile`: ignored with a warning.
- Unknown profile from `--profile` / `JAS_PROFILE` → `core.ExitUsage`, naming available profiles. From config → warning, fall back to `default`.
- `default/` is created when missing, best effort; a read-only home runs with an empty in-memory `default`, no warning, no exit.
- Read exception: only the **active** profile's `<home>/profiles/<active>/skills/`, only for discovery and read-only tools. `Resolve` (write/edit) and `DeniedToken` (shell filter) keep the full floor. Other deny patterns (`.env*`, keys, `secrets/**`) still apply inside.
- User skill sources: only the active profile's `skills/` and the built-in manual. `~/.agents/skills`, `~/.claude/skills`, `<UserConfigDir>/jas/skills` are no longer read. Project sources unchanged.
- Manual skill installs to `<UserCacheDir>/jas/manual/` (layout `jas/SKILL.md`), loaded last so a same-named profile or project skill overrides it.
- System prompt: profile `AGENTS.md` section before the project instructions section.
- Config scope flag is `--in-profile` (CLI and `/settings`); `--profile <name>` only picks the profile.
- Never append to the session log from `Update`; log from a `tea.Cmd` (AGENTS.md).
- `go test -race ./...` green, `CGO_ENABLED=0`. Commits `type: description`.
- Docs follow features in the same commit as the user-visible change (AGENTS.md): `docs/manual.md`, `make manual` copy, README, `docs/design.md`, repo `AGENTS.md`.

## Review Focus

1. **Symlink inside a profile skill pointing into the jas home** (`skills/x/creds -> ~/.jas/auth.json`): reading it must be refused; the lift applies to the resolved path only when that resolved path is inside the active profile's `skills/`. Test in Task 2.
2. **`JAS_HOME` set to a directory outside `$HOME`** (CI): profile skills still discovered and readable, catalog prints an absolute path, the moved-home absolute deny pattern is lifted only under `skills/`. Test in Task 2 and Task 4.
3. **Project commits `"profile": "ds"` but the project is untrusted**: the profile is chosen from global/default, not `ds`, and no warning about `ds` is printed. Test in Task 1.
4. **`/profile` to the profile already active, or `/profile` while a run is going**: same-name switch is a cheap reload with the normal notice; mid-run is refused with the existing wait notice. Test in Task 7.
5. **Existing user with skills in `~/.agents/skills` upgrading**: session still starts, skills are absent, one notice names the old folders and the new path, and it does not repeat on the next start. Test in Task 8.
