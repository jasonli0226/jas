# `jas dream` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reviewed memory cleanup command: `jas dream` reads recent event logs plus the profile memory store, writes a proposed store and a cited report, and `jas dream apply|discard|undo|diff|list` let the owner act on it.

**Architecture:** A new `dream` package holds everything that needs no model: dream records and the watermark, snapshot and hashing, lint, log-window selection, the evidence digest, the two dream-only tools and the write guard, verification, the report, and apply/discard/undo. `cmd/jas/dream_cmd.go` wires it to the existing agent loop (`core.Run`): it copies the store into a temp workspace outside the jas home, runs one session there with read/ls/grep/write/edit plus the dream tools and no approval gate, then copies the result back to `~/.jas/profiles/<p>/dreams/<id>/proposed/`. The workspace is a builder choice from the spec's "left to the builder" list: it keeps the jas home deny floor intact for the model, and the spec's storage layout is what persists.

**Tech Stack:** Go (stdlib), existing `core`, `memory`, `tools`, `settings` packages.

**Spec:** `docs/superpowers/specs/2026-11-13-jas-dream-design.md`

## Global Constraints

- Nothing changes the live `memory/` except `apply` and `undo`.
- Dreams live at `~/.jas/profiles/<profile>/dreams/`: `state.json`, `<id>/{dream.json, report.md, evidence.md, proposed/, before/}`.
- Id: `<UTC timestamp>-<4 hex>`, same shape as `core.NewSessionID`.
- States: `pending`, `applied`, `discarded`, `stale`, `undone`.
- Defaults: `--max-tokens` **400000**, `--timeout` **20m**, watermark fallback **30 days** ago, at most **50** sessions, keep the newest **10** dreams, digest cap **200 KB**, each quoted string trimmed to **2 KB**, large-removal warning when more than **one third** of notes are removed, promotion hint at **3** sessions.
- Exit codes: existing only — `0`, `1` (failure; apply/undo refused; diff on wrong state; memory off), `2` (usage; `apply` off a terminal without `--yes`), `7` (cap reached, proposal still written), `130` (interrupted, no proposal).
- `<id>` default: `diff`/`apply`/`discard` → newest `pending`; `undo` → newest `applied`.
- Watermark moves to the dream's `ended_at` on apply and discard; undo does not move it back; `--since`/`--sessions` change selection only.
- Inside `proposed/`, every live write rule holds (folder rule, `.md` only, valid frontmatter on notes, secrets refusal) except the `MEMORY.md` edit-only rule.
- `remove_note` refuses `MEMORY.md`; removes a `projects/<key>/` folder left empty.
- Evidence and logs are quoted data; the dream can write only inside `proposed/`. No shell, no web.
- Event-log additions are additive (v1 stays): `session_started.dream {id, window_sessions}`, `dream_proposed`, `dream_applied`, `dream_discarded`, `dream_undone`.
- `go test -race ./...` green, `CGO_ENABLED=0`; commits `type: description`; never log from `Update`.
- Docs follow features (AGENTS.md): `docs/manual.md`, `make manual` copy, `README.md`, built-in skill, `docs/event-log.md`, `docs/design.md` §5/§12.3, same commit as the feature.

## Review Focus

1. **`memory/` is a symlink** to a folder outside the jas home (allowed by the memory lift) → apply writes the proposal into the link's target and keeps the link; it never replaces the link with a plain folder (Task 8 test `TestApply_SymlinkedMemoryKeepsLink`).
2. **Torn or newer-`v` lines in a session log** → window selection and the digest skip the line, note it in the digest, and keep going (Task 4 test `TestSelectWindow_SkipsTornLines`, Task 5 test `TestEvidence_NotesSkippedLines`).
3. **Empty or missing store** → a dream still runs; apply creates `memory/`; undo of that apply removes it again (Task 8 test `TestApplyUndo_MissingStore`).
4. **Ctrl-C during the model pass** → exit 130, no `<id>/` left behind, temp workspace removed, `list` shows nothing new (Task 9 test `TestDreamCmd_InterruptLeavesNothing`).
5. **Project folder with a hashed key** (path over 200 bytes; `memory.DecodeKey` returns `ok=false`) → lint never reports it as "project gone" (Task 3 test `TestLint_HashedKeyNotGone`).

### Task 9: `jas dream` (the run)

**Files:**
- Create: `cmd/jas/dream_cmd.go`, `cmd/jas/dream_cmd_test.go`
- Modify: `cmd/jas/main.go` (dispatch `dream`, usage text), `cmd/jas/setup.go` (setup without a project), `docs/manual.md` + `make manual` copy (the run: flags, defaults, exit codes, storage layout, watermark)

**Interfaces:**
- Consumes: everything in `dream`; `core.Run`, `core.Executor`, `core.NewTokenPool`, `core.OpenEventLog`, `tools.Read{}`, `tools.Ls{}`, `tools.Grep{}`, `tools.Write{}`, `tools.Edit{}`; `askLine`, `isTerminal`, `memorySetting`, `memory.ResolveMode`.
- Produces: `dreamCmd(ctx context.Context, args []string) error`; `prepareNoProject(ctx context.Context, flags map[string]string, root string) (*env, error)` — `prepare`'s settings, profile, auth, redactor and provider resolution with global and profile layers only (`ForProject(false)`), no trust prompt, no project skills or context, no memory section, `root` as given. Refactor `prepare` to share the code rather than copy it.
- Flow (`jas dream [--since <dur|date>] [--sessions n] [--max-tokens n] [--timeout dur] [--json] [--profile name]`):
  1. `prepareNoProject` with a fresh `os.MkdirTemp("", "jas-dream-")` workspace as root; remove it on return.
  2. Memory mode from global/profile layers; `ModeOff` → exit 1 "memory is off for this profile".
  3. Live dir = the profile memory dir; refuse (exit 1) when the policy's `ProfileMemoryIgnored()` is non-empty.
  4. `NewID`, `HashTree(live)` → `Base`, `CopyTree(live, ws/proposed)`, `Lint` (before).
  5. `SelectWindow` (since = `--since` or watermark; limit = `--sessions` or 50); copy each selected log to `ws/logs/<session-id>.jsonl`; `BuildEvidence` → `ws/evidence.md`; `IndexSeqs`.
  6. Executor: registry of the five file tools plus `ReportChange`, `RemoveNote(ws/proposed)`; `Gate` nil; `WritePrecheck`/`WriteGuard` from `dream.Guard`; policy `{Root: ws, Deny: denyPatterns(home)}`. Session log at `<home>/sessions/<session id>/events.jsonl`; `SessionMeta` = `e.sessionMeta(model)` plus `"dream": {"id", "window_sessions"}`. `core.Run` with `dream.SystemPrompt`, `dream.Kickoff`, `Tokens: NewTokenPool("dream", maxTokens, nil)`, ctx with the timeout.
