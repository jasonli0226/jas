# jas v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single static Go binary, `jas`, that runs a real coding task end to
end against any OpenAI-compatible endpoint, with the safety, budget, event-log
and config guarantees listed in design §4.

**Architecture:** A provider-neutral streaming agent loop (`core`) talks to one
OpenAI chat-completions adapter (`providers`), executes built-in tools
(`tools`) through a batching executor with an approval gate, and writes every
step to a versioned, single-writer JSONL event log. Config is resolved from
flags > `JAS_*` env > `~/.jas/config.json` > defaults (`settings`). The CLI in
`cmd/jas` wires everything together.

**Tech Stack:** Go 1.27, standard library first. Allowed dependencies:
`golang.org/x/sync` (errgroup), `golang.org/x/term` (TTY detection, no-echo
key input), `github.com/bmatcuk/doublestar/v4` (`**` globs). Nothing else
without updating this plan.

**Spec:** [docs/design.md](../design.md) (§3, §3.1, §4, §7, §9, §10, §11) and
[docs/use-cases.md](../use-cases.md) §1–§3. Read both before starting.

## Global Constraints

- Module path `github.com/jasonli0226/jas`; `go 1.27` in `go.mod`.
- Build: `CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" ./cmd/jas`. Binary < 15MB; `jas --version` cold start < 50ms.
- Package layout follows design §3: `core/`, `providers/`, `tools/`, `settings/`, `cmd/jas/`. Test helpers go in `internal/testutil/`.
- Never call `os.Chdir`. The project root travels in `core.ExecPolicy.Root`; shell children get it as `cmd.Dir`.
- No `--api-key` flag. Keys come from `auth.json`, an `$ENV` reference stored there, or `JAS_API_KEY`.
- `~/.jas/` is created `0700`; `auth.json` and `trust.json` are written `0600`. `JAS_HOME` overrides `~/.jas` (tests use a temp dir).
- Tool errors are tool results with `status: error`, never Go errors out of the loop.
- Exit codes (design §3): 0 final answer · 1 provider/config/internal · 2 usage · 3 context full · 4 turn cap · 5 approval needed, no TTY · 130 interrupted.
- Defaults: `max_turns` 50, `max_tool_output` 32768 bytes, `elide_at` 0.6, `keep_tool_results` 6, unknown-model context window 128000, shell timeout 120s, SSE idle timeout 60s, provider retries 3 (backoff 1s, 2s, 4s; honor `Retry-After`).
- Token estimate for messages without reported usage: `len(bytes)/4`.
- Commit messages: `<type>: <description>` (feat, fix, refactor, docs, test, chore, perf, ci).
- Platforms: Linux and macOS only in v1. Files using `Setpgid`/`syscall.Kill` carry `//go:build unix`.
- CLI tests share one binary: `testutil.JasBinary(t) string` builds `./cmd/jas` once per `go test` process (`sync.Once`, into `os.MkdirTemp`) and returns its path.
- Every task ends with `go vet ./... && go test ./...` green.

## Review Focus

1. **Output with no newlines or invalid UTF-8** (minified JS, binary files): truncation must still cap at `max_tool_output`, and the JSON sent to the provider must stay valid (invalid bytes replaced with U+FFFD). Tests in Task 5.
2. **Malformed tool-call arguments or an unknown tool name** from the model: the call gets an `error` result and the run continues. Tests in Task 4.
3. **Ctrl-C while an approval prompt is waiting or a parallel read batch is running:** every dangling call gets a `cancelled` result, `session_ended` is written, exit 130. Tests in Tasks 6 and 9.
4. **Symlink inside the root that points at a deny-floor file** (e.g. `config -> .env`): refused by the resolved-path deny check. Test in Task 11.
5. **CRLF files and `old_string` that only matches with different line endings:** `edit` reports not found rather than corrupting the file, and preserves CRLF on a successful edit. Test in Task 7.
